# UX 친화성 체크리스트 (오너 11-20 "모든 부분을 사용자 친화적으로")

허브 `docs/team/QUALITY.md` 5장과 같은 10항목을 샌드랩에 맞춘 것. 화면·공통 컴포넌트 PR마다 본다.
**자동** 표시는 검사가 떨어뜨린다: `pnpm build:preview && node scripts/qa/sheet-e2e.mjs`(= `pnpm qa:preview --only sheet`), `src/ui-next/sheet/sheet.test.tsx`.

1. **누르는 영역 44×44 이상**(S9 `--sl-hit`). 문장 속 링크(inline `<a>`)는 WCAG 2.5.8 예외. **자동**: sheet-e2e `ux`(390 터치, 14쪽, elementFromPoint로 실제 눌리는 범위 — 양성 대조 포함)·시트 안 전부.
2. **모달은 공통 `BottomSheet`(src/ui-next/sheet) 하나로** — 손잡이 끌기(높이 25% 또는 0.5px/ms 튕김이면 닫힘, 아니면 복귀)·손잡이 탭/Enter/Space·배경 탭·Esc·뒤로 가기·닫기 버튼이 같은 길과 같은 퇴장 모션. 768px 이상은 카드라 손잡이가 숨으니 내용에 Close 버튼을 둔다. **자동**: sheet.test '모달은 BottomSheet 하나로'(손으로 만든 `<dialog>`·`showModal`·`role="dialog"`·`aria-modal`이 생기면 실패), sheet-e2e(짧게→복귀, 길게→닫힘, 튕김→닫힘, 안쪽 스크롤과 충돌 없음, 배경 탭·Esc·뒤로 가기·Space·Close 연타).
   - **예외(모달이 아님)**: 게임(시뮬) 판 위 덮개 — Spill 결과 화면(`SpillResult`, 헤더가 살아 있는 화면이라 `role="dialog"` 대신 이름 붙은 region), 옛 결과 카드(`ResultCard`, prod 전용·P12 컷오버 때 삭제), 판 위 토스트·손 안내. 이것들은 가둘 것도 닫을 것도 없다 — 뒤로·소리·메뉴는 헤더에 있다.
3. **모달 뒤 배경이 스크롤되지 않고, 닫히면 원래 자리**. **자동**: sheet-e2e '배경 스크롤 잠금'(휠·배경 스와이프).
4. **포커스**: 열면 안으로, Tab 가둠, 배경 inert, 닫히면 연 버튼으로. 연 버튼을 시트가 열린 동안 지우지 않는다(지우면 포커스가 body로 샌다). **자동**: sheet-e2e 'Esc(포커스 복귀)'·홈 공유 'Share로 복귀'.
5. **history 빈칸 없음**: 시트를 닫은 뒤·시트 안 링크로 이동한 뒤 뒤로 가기 한 번에 이전 페이지. 시트가 열린 동안 주소를 바꾸지 않는다(바꿀 주소는 onClose에서 — 홈 공유). **자동**: sheet-e2e '길게 끌면 닫힘 + history 빈칸 없음'·'시트 안 링크'·'홈 공유 시트'. 범위 밖(허브와 같음): 시트를 뒤로 가기로 닫은 뒤 **앞으로 가기**를 누르면 시트 칸(닫힌 상태)에 온다 — history 칸 방식의 한계.
6. **모션 줄이기면 즉시** — 등장·퇴장·복귀 모두. JS 지연(animation-delay·setTimeout)도 같이 끈다. **자동**: sheet-e2e '모션 줄이기'.
7. **입력칸 글자 16px 이상**(iOS 포커스 확대 방지), viewport meta로 확대를 막지 않는다, 390에서 가로 넘침 0. **자동**: sheet-e2e `ux`(입력 16px·확대 막음·가로 넘침), 시트 안 입력.
8. **누르면 바로 반응**: 누름 모양, 기다리는 동안 문구('Making a link…'·'Publishing…'), 끝나면 결과 문구(토스트). 검사 불가 사유: '느낌'은 화면을 봐야 한다 — 캡처·녹화로 리뷰.
9. **실수는 되돌릴 수 있게**: 판을 지우는 버튼(Clear·Retry 길게 누르기)은 Undo 또는 확인. 검사 불가 사유: 화면마다 뜻이 달라 리뷰에서 본다.
10. **스크롤 갇힘·길게 누르기 의존 없음**: 판 위 `touch-action:none`은 판 크기만, 길게 누르기·호버 동작은 탭·버튼으로도. 검사 불가 사유: 입력 설계 문제라 플레이 테스트(첫 10초)에서 본다.

숫자(25%·0.5px/ms·6px 판정·280/240/300ms·768px)는 허브와 같다 — 두 사이트의 손맛을 맞춘다(DECISIONS 2026-11-20 '공통 BottomSheet 이식').
