## 3. 기획 v1

### 3.1 비주얼 시스템(초안)
- **톤**: 어두운 개발 툴 → 따뜻한 장난감 퍼즐. 보드 주변 배경은 크림/따뜻한 베이지 계열의 밝은 테마 또는 깊은 남색+따뜻한 하이라이트 중 **시안으로 비교 후 결정**(A: 크림 라이트, B: 딥 인디고 다크 — 시안 3장은 우선 A로 요청, B는 라운드 2에서 A가 약하면). 보드 캔버스 자체는 어둡게 유지해도 재료 색이 살아야 함.
- **재료 색 체계**(UI 칩·진행 링·캔버스 공용): 모래 #F2C14E, 물 #4DA8E8, 돌 라벤더 회색, 용암/불 #FF7A45, 성공 민트 #3DD6A8, 위험 코랄 #FF5A4F. 색만으로 구분하지 않고 아이콘 모양을 같이 쓴다.
- **형태**: 12~20px 둥근 모서리, 알약 칩, 입체 버튼(눌림 2px), 그림자 부드럽게. 이모지 문자 아이콘(⟲ ↺ ⏩ ☰) → SVG 아이콘 세트.
- **타이포**: 숫자 tabular, 제목 굵게. 웹폰트 추가 없이 시스템 폰트 우선(성능·AdSense 영향 최소).
- **마스코트**: 모래 정령(작고 둥근 몸, 점 눈) 1종. 5단계에서 통합. Gemini는 전신 포즈 통째로, 글자 없이.

### 3.2 단계 출시(각 단계 390px 캡처 + 독립 혹평 6.5점 이상)
1. **HUD·목표 칩·컨트롤 재배치**: 상단 슬림 바(뒤로·레벨명·소리·일시정지), 보드 위 목표 칩(아이콘+진행 링, 달성 시 체크), 별 목표(par)는 칩 옆 별 3개 상태, 컨트롤(RUN·삽·되감기·배속)을 하단 중앙 엄지 영역으로, 보드를 가리는 떠다니는 원형 버튼 제거. 색 토큰 도입.
2. **클리어/실패 연출**: 별 시차 채움(기존 `starGapMs` 활용)+소리·진동, 한 줄 격려, 다음/다시/공유 CTA 위계(주 버튼 1개). 일반 클리어 1초 안, 3별·스트릭만 큰 연출. `prefers-reduced-motion` 대응.
3. **재료 렌더**: 모래 반짝임·물 윗면 하이라이트(성능 예산 내, 모바일 60fps 확인 필수 — 벤치 `/spill/bench`).
4. **레벨 선택 지도**: 월드별 길 위 노드, 별·잠금·현재 강조, 월드 2 불 예고, 데일리 카드. (URL 구조 불변)
5. **마스코트 통합**: 온보딩·실패·클리어.

### 3.3 첫 단계(①) 완료 조건
- 390px에서 목표가 보드 위 칩으로 3초 안에 읽힌다, 컨트롤 전부 하단 44px 이상 타깃, 보드 가림 요소 0, 기존 접근성 라벨 유지(테스트 `render.test.tsx` 통과), `spill:verify` 전 레벨 PASS(UI만 바꿨으니 결과 동일), verify-ads 통과.

## 4. 사용자 질문 (7)
1. **처음 온 사람**: 지금은 목표가 보드 아래 텍스트라 3초 안에 안 읽힘 → 목표 칩을 보드 위·항아리 가까이로. 근거: 코드 확인(GoalDock) + 레퍼런스(목표는 오브젝트로). 시안 후 390px 실측 필요.
2. **왜 계속 하나**: 별 시차·한 줄 격려·"다음" 단일 주 버튼, 데일리 스트릭은 서버 준비(리더보드 S0~S2) 후. 지도(4단계)에서 다음 노드 강조.
3. **왜 졌나**: 실패 문구는 이미 2-1 작업에서 불 전용 문구가 있음. 질책 없는 즉시 재시작을 하단에 둔다. 숫자 근거(사람형 시뮬)는 UI 변경이 난이도에 영향 없으므로 해당 없음.
4. **어떻게 쓰나**: 엄지 영역 재배치가 핵심. 연타·뒤로가기·탭 숨김은 구현 직후 멍청한 사용 시험으로 확인(미실시). 색만 구분 금지 규칙 적용.
5. **왜 공유하나**: 스포일러 없는 결과 격자(Wordle 원리)를 기존 `shareText`에 검토. 3별 순간에 마스코트 컷(5단계).
6. **우리 사이트에서 왜**: 경쟁작 불평 1순위가 광고 마찰(WMW2·Sand Balls). 샌드랩은 게임 화면 광고 없음·레벨마다 공략 있음 → 개편의 약속에 "방해 없는 퍼즐"을 포함.
7. **오너가 보면**: "아직도 딱딱하다/그냥 색만 바꿨네"가 가장 가능성 큼 → 1단계에서도 형태(알약·입체 버튼·SVG 아이콘)와 연출 한 가지는 같이 넣는다. 다크 vs 라이트 선택이 취향 갈릴 수 있어 시안 A/B 모두 평가.

# 부록 R2 — 라운드 2 반증 + 기획 v2 (2026-11-19 06시 세션)
> 시안 3장 생성 확인(`public/art/spill-ui-sketch-{a-hud,b-clear,c-map}.webp`). 독립 리뷰는 13시 세션.

## R2-1. 시안 평가
- **A HUD**: 크림 프레임 안에 어두운 갈색 배경의 둥근 보드, 보드 위 항아리+진행 링 칩 2개, 하단 중앙 큰 주황 RUN + 양옆 삽·되감기 원형 버튼. 목표가 오브젝트(항아리)로 읽히고 엄지 영역에 컨트롤이 모인다 → **채택**. 한계: 시안의 보드는 재료 질감이 CSS로 불가(3단계 셰이더 영역) — 1단계는 프레임·칩·버튼만.
- **B 클리어**: 별 3개 시차 채움, 큰 "다음"·보조 2개(다시·공유) → 채택(2단계). 시안 속 글자는 코드 텍스트로 대체(AI 글자 신뢰 안 함).
- **C 지도**: 구도 좋으나 보라 선인장 마스코트가 모래 정령과 다름 → 4~5단계에서 마스코트 확정 후 재생성(비용 ≈ ₩100). 지금은 사용 안 함.

## R2-2. 반증 리서치 결과 (WebSearch 2건, 11-19)
1. **다크 vs 라이트**: 캐주얼 퍼즐에서 테마가 리텐션에 미치는 *신뢰할 만한 데이터는 찾지 못했다*(블로그의 "다크 30일 리텐션 +22%"는 출처 불명 → 근거 불인정). 결론: 취향 논쟁이 아니라 **대비·가독성**이 핵심(Beads Out 비판: 베이지·흰·회색 혼동). → 결정: UI 크롬은 **크림 라이트(A)**, 보드 캔버스 배경은 어둡게 유지해 재료 대비 확보. 모든 색은 `C` 토큰 한 곳이라 B(다크)로 되돌리기 쉽다. 오너 시안과 1주 데이터(전환·reset)로 사후 판정.
2. **엄지 영역/HUD**: 주 조작은 하단, 상단은 내용·덜 쓰는 기능, 동시 노출 컨트롤은 5~6개 이하, 하단에 컨트롤 쌓기는 피함(Creative Bloq·Epic 문서 요약). 로(rough) 가이드일 뿐 기기마다 다름(Monterail). → 하단 컨트롤은 **한 줄 3개(삽·RUN·되감기)**, 배속·일시정지·소리는 상단 슬림 바로(덜 쓰는 기능). 하단에 쌓지 않는다.
3. 확인 못 한 것: 퍼즐 게임 목표 칩 배치의 구체 사례(검색에 안 걸림) → 시안과 390px 실측으로 대체.

## R2-3. 기획 v2 — 1단계 범위(확정)
- `ui.ts`: 토큰 확장(크림 배경 `#FFF6E3` 계열, 잉크 텍스트 짙은 갈색, 재료색 4종·성공·위험, 반경 12/20, 입체 버튼 그림자) + 보드 프레임 색. 기존 export 이름 유지(호출부 무수정).
- `Hud`: 슬림 상단 바(← 레벨, 이름, 소리·일시정지 SVG 아이콘). 이모지 ☰🔊⏸ 제거. moves·par는 칩으로.
- `GoalDock`→**목표 칩**: 재료 아이콘(색+모양)+원형 진행 링+달성 체크. 보드 위(또는 바로 아래 가까이)에 가로 배치, 나쁜 목표(☠)는 코랄 칩. 접근성: 색만으로 구분 금지(모양·텍스트 `aria-label` 유지).
- `FloatButtons`: 보드 위 떠다니는 원형 제거 → 하단 중앙 줄로 이동(RUN 큰 주황, 삽·되감기 알약). 배속은 일시정지 옆 상단.
