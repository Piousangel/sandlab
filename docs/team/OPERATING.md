# 팀 운영 규칙 (2026-11-13 개정)

06:00 아침 팀(클라우드 루틴)은 루틴 프롬프트의 절차(회의 → 리뷰 → 반영 → 보고)에 더해 **이 문서를 따른다.** 프롬프트와 충돌하면 이 문서가 최신이다(금지 규칙은 프롬프트·CLAUDE.md가 우선).

## 1. 회의 전에 더 읽을 것
- [direction.md](./direction.md): 팀이 지금까지 배운 것과 현재 방향
- [above-the-fold.md](./above-the-fold.md): 첫 화면 현황과 실험 기록
- 최근 회고 `docs/team/retros/` 최신 1개
- 어제 게시 결과 `docs/marketing/posted.json`

## 2. 회의록에 추가되는 칸
회의록 맨 위에 **어제 회고**를 쓴다.
- 어제 반영한 것이 실제로 어땠나(지표 숫자, 실사이트 확인, 게시 반응). 측정할 수 없으면 "측정 불가 — 이유"라고 쓴다.
- 잘된 점 1줄, 부족했던 점 1줄, 다음에 다르게 할 것 1줄.

## 3. 상시 안건: 첫 화면(above the fold)
사용자 결정(11-13): **사이트 최상단은 가장 중요한 땅이다.** 매일 회의에서 다룬다.
- **QA**: 홈(샌드박스)과 /play·/daily·주요 공략 페이지의 첫 화면을 데스크톱(1366×768)과 모바일(390×844) 기준으로 본다. 스크롤 없이 무엇이 보이는지 적는다. 실사이트에 접근할 수 없으면 로컬 빌드로 확인하고, 접근할 수 없었다고 적는다.
- **PM**: 후보 3~5개 중 최소 1개는 첫 화면 아이디어여야 한다.
- 첫 화면 변경은 **한 번에 실험 1개**만 진행한다. 7일 동안 측정한 뒤 유지하거나 되돌린다. 가설, 변경, 측정 지표, 결과를 above-the-fold.md 실험 표에 남긴다.
- 금지(기존 규칙 유지): 캔버스·게임 화면 안의 광고, 공유 URL 형식·격자(1200×600) 변경, 댓글 기능, 시뮬 품질 작업. 첫 화면을 바꿔도 샌드박스(핵심 훅)는 없애지 않는다.

## 4. 방향 문서와 주간 회고
- **direction.md**: 방향이 바뀌거나 배운 점이 생긴 날에 갱신한다(같은 PR). 항목은 '현재 방향', '부족한 점', '보완한 것(날짜·PR)', '앞으로', '버린 방향'이다. 오래되거나 틀린 줄은 지운다. 쌓아두기만 하지 않고 정리한다.
- **월요일 주간 회고**: `docs/team/retros/YYYY-Www.md`에 쓴다.
  - 지난 7개 회의록과 지표를 요약한다.
  - 효과가 있었던 것과 없었던 것을 숫자로 적는다.
  - 다음 주 목표 1~2개를 측정할 수 있는 형태로 정한다.
  - 회고 결과로 direction.md를 갱신한다.
  - 월요일 메일 본문 첫 줄에 회고 요약을 넣는다.

## 5. 마케팅: 실제 게시
마케터가 쓴 글을 실제로 올린다. 자격증명은 에이전트 세션에 두지 않는다. 게시는 GitHub Actions가 한다(배포와 같은 구조).
1. 마케터는 같은 PR에 `docs/marketing/queue/YYYY-MM-DD.json`을 넣는다(형식은 `scripts/post-social.mjs` 맨 위 주석).
2. main에 머지되면 `marketing-post.yml`이 실행된다. URL이 200이 될 때까지(배포 완료) 기다렸다가 게시하고, 결과를 `docs/marketing/posted.json`에 커밋한다.
3. 다음 날 회의에서 결과를 확인한다(posted, error, skipped). 자격증명이 없어 skipped면 메일의 '사람이 결정할 것'에 적는다.

게시 규칙:
- 채널마다 하루 1건(스크립트가 강제한다).
- 지원 채널: `bluesky`, `x`, `reddit`.
- 홍보보다 가치를 먼저 준다. 시뮬레이션 결과, 공략, 재미있는 사실 같은 것이다. 링크는 홈보다 해당 공략이나 게임 페이지로 건다.
- 채널마다 글을 고쳐 쓴다(복붙 금지). Reddit은 서브레딧의 자기 홍보 규칙을 확인하고 맞는 곳에만 올린다. 같은 서브레딧은 주 1회 이하.
- 사이트에 실제로 있는 내용만 쓴다(과장, 가짜 후기 금지).
- 사람이 결정해야 할 일이 생기면 메일로 알린다.
- API가 없는 커뮤니티(국내 커뮤니티 등)는 기존처럼 `docs/marketing/YYYY-MM-DD.md` 초안만 쓰고 사람이 올린다.
- 메일 답장, 댓글 응대, DM은 하지 않는다.

## 6. 막혔을 때
- 지표 파일이 없으면 GitHub 예약 실행 누락일 수 있다. 회의록에 적고 진행한다. 사람이 `gh workflow run metrics.yml`로 다시 돌릴 수 있다.
- 실사이트 curl이 막히면(프록시 403) 그 사실을 회의록에 적는다. 메일에서 환경의 허용 도메인 추가를 요청한다.
