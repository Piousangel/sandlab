# 샌드랩 랭킹·경쟁 구조 방향 (오너 11-18) — 미니게임 허브와 같은 맥락

> 상태: 방향 확정 + 라운드 1 조사(서버 옵션) 완료. 허브 쪽 전체 맥락·조사: minigames-hub `docs/team/specs/2026-11-18-leaderboard-direction.md`. 이 문서는 샌드랩에 맞춘 해석이다. 세부는 팀이 라운드 2(반증)→기획 v2→독립 리뷰로 정한다(오너에겐 묻지 않는다).

## 오너 방향
리더보드(랭킹)를 키워 **경쟁 심리**를 올리고 사람들이 **매일** 들어와 플레이하게 한다. 최신 순 노출, 순위를 눈에 띄게, 서버 개발로 시도할 것 탐색. 게임(퍼즐) 퀄리티도 계속 발전해야 한다.

## 샌드랩 사실 (조사 요약, 원문 `docs/design/leaderboard/R1-server-options.md`)
- 사용 저장소: D1 1개 + Analytics Engine 1개(KV·DO·R2 없음). 갤러리·점수는 D1.
- Spill은 WebGPU가 아니라 **CPU 160×240 결정적 시뮬**이고 Replay 포맷이 이미 있어 서버 재시뮬 검증이 가능하다. 단 틱당 2~6ms(수백 틱 0.5~4초, 2700틱 약 13초)라 **Workers 무료 CPU 10ms로는 불가 → Workers Paid 필요**(오너 결제, 팀은 시점·금액만 메일로 요청). 모래 데일리(WebGPU)는 재생 검증 불가.
- 현재 Spill 일일 기록은 localStorage(`sandlab.spill-daily.v1`)뿐이라 **서버 순위가 없다**. 즉 랭킹을 만들려면 점수 수집 API부터 필요하다.

## 샌드랩의 랭킹 후보(팀이 라운드 2에서 선택·반증)
| 후보 | 내용 | 비용 |
|---|---|---|
| 일일 Spill 랭킹 | 오늘 퍼즐의 별·수(moves) 기준, "오늘 N명 중 상위 P%", 오늘 해법 분포("1수 클리어 14%") | 중(수집 API+집계) |
| 레벨별 최소 수 기록 | 레벨마다 최소 moves 보드, 내 기록과 최소의 차이 | 중 |
| 연속 스트릭·주간 정리 | 연속 클리어 일수, 주간 챔피언 | 소 |
| 서버 재시뮬 검증 | Replay 제출 → 서버 재시뮬(Paid 필요) | 대(S3) |
허브와 같은 단계: **S0 서버 기반(점수 API·한도·필터·IP 해시, 조회 캐시) → S1 제출 직후 순위·백분위 → S2 일/주 보드·player_id·닉네임 → S3 재시뮬 검증·시즌**.

## 규칙
- 샌드랩 외부 게시는 사람이 한다(팀은 초안만). 서버 비용·유료 전환은 오너 결제가 필요하니 코드로 시도하지 않는다.
- 개인정보: 원본 IP 저장 금지(해시, 샌드랩은 이미 해시), 닉네임 정책은 Terms에 명시.
- 일일 Spill 번호는 UTC 기준 `dayNumber`와 `dailyIdFor`로 이미 통일돼 있다(11-18 홈 카드 수정 #49). 랭킹도 같은 번호를 키로 쓴다.
