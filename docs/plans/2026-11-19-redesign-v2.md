## 0. 목표 · 하지 않을 것 · 완료 기준

**목표**: "2000년대 초반 같다"(오너)를 끝낸다. 처음 온 사람이 3초 안에 "부어 보면 된다"를 알고, 데일리(Spill)가 매일 돌아오고 싶은 화면이 된다. UI가 유리와 모래라는 물질로 만들어져, 스크린샷 한 장으로 샌드랩임을 알 수 있다.

**하지 않을 것**
- 엔진 변경(셰이더·격자 1200×600·캔버스 empty #07090D). 셀 수 카운터·Undo 같은 엔진 비용 기능(측정 후 별도 판단).
- 시안의 가짜 정보: SPECIMEN 번호, "CELLS MOVING", 눈금자·"1200×600 CELLS·WEBGPU", 그날 레벨 재료로 지층 색 정하기.
- S2 진열장의 황동·세리프·양피지(스큐어모피즘). 사운드 키트·9:16 스토리 카드·시험관 루프 18개 동시 재생(컷오버 이후).
- 공유 링크(`#s=`, `#g=`, `/s/:id`) 형식 변경, 게임·캔버스 화면 안 광고, AdSense 재심사 신청.

**완료 기준(컷오버 게이트)**
- 골든셋 링크(`#s=` 포함 10개) e2e 통과, 옛 저장 데이터(`sandlab.spill-daily.v1`, `sandlab.daily.v1`) 100% 읽힘.
- Lighthouse 모바일 LCP ≤ 2.5s, CLS ≤ 0.05, INP ≤ 200ms, axe serious 0, 대비 검사 스크립트 통과.
- 3초 테스트(처음 보는 사람 5명 중 4명이 첫 화면에서 바로 붓기 시도) — 팀 내 서브에이전트 '처음 온 사용자' 시뮬 + 오너 확인.
- 72시간 지표(첫 붓기율·daily start→clear)가 15% 넘게 나빠지면 롤백(빌드 변수 1줄).

## 2. 데이터 모양 (UI보다 먼저, 순수 함수 + 테스트)

```ts
// src/lib/spill/client/daily.ts (확장, 키 불변)
export type DailyRec = { stars: number; moves: number; ticks?: number; mask?: number /* CLEAR|GEM|PAR 비트 */ }

// src/lib/strata.ts — 지층 역산(옛 키 sandlab.daily.v1 + 새 키 병합)
export type Stratum = { dayNumber: number; dateUTC: string; material: MaterialId /* 순환표 */; stars: 0|1|2|3; missed: boolean }
export const STRATA_CYCLE: readonly MaterialId[] // 대비 좋은 10종, 순서 고정(DECISIONS 기록)
export function readStrata(storage: Pick<Storage,'getItem'>, today: number, days = 30): Stratum[]

// 공유 텍스트 v2: 레벨 id 제거, 이모지 대신 유리알 문자 규칙
export function shareTextV2(rec: DailyRec, dayNumber: number): string
```
테스트: 손상된 JSON·옛 키만 있는 경우·결측일·UTC 자정 경계·9일 주기에서 띠 색이 10종 순환하는지.

### P5 메모 — "오늘 클리어한 사람 중 상위 N%" 서버 집계 제안(구현 안 함, 다음 판단용)

P5는 자리와 인터페이스만 넣었다: `DailyStanding {topPercent, sample}`(src/ui-next/shell/spillTypes.ts) → `standingLine()`이 값이 없거나 표본 < 50이면 null → 결과 화면은 줄 자체를 그리지 않는다. 지금 DailySpill은 항상 `standing: null`을 넘긴다(가짜 수치 0). 아래는 그 값을 채울 서버 쪽 제안이다.

- **테이블(D1, 마이그레이션 0002)**: `spill_daily (day INTEGER, pid TEXT, ip TEXT /*SHA-256 앞 12바이트, 갤러리 votes와 같은 방식*/, level_id TEXT, lh TEXT, moves INTEGER, ticks INTEGER, mask INTEGER, created_at INTEGER, PRIMARY KEY (day, pid))` + 인덱스 `(day, moves, ticks)`. 기존 `spill_hist`(레벨 전체 기간 분포)와 분리 — "오늘"은 날짜 단위라 같은 테이블로 못 센다.
- **제출 라우트**: `POST /api/spill/daily/:day/clear {pid, lh, moves, ticks, mask}`. 첫 클리어(공식 기록)만 클라이언트가 보낸다(연습 판은 안 보냄, S4). 서버는 `INSERT OR IGNORE`라 같은 pid의 둘째 제출은 무시. day는 서버 시계로 오늘·어제(UTC 자정 경계 유예 1시간)만 받는다. 검증은 기존 `validateLevelClear` 재사용(lh 일치·moves 1~32·ticks 하한 par×0.4~2700) + level_id = `dailyIdFor(day)`.
- **조회 라우트**: `GET /api/spill/daily/:day/standing?moves=&ticks=` → `{topPercent, sample}`. 순위 = (moves 오름차순, ticks 오름차순)에서 나보다 앞선 수 / 전체. `SELECT COUNT(*) … WHERE day=? AND (moves<? OR (moves=? AND ticks<?))` + `COUNT(*) … WHERE day=?` 두 줄(인덱스로 충분, 하루 수천 행 가정). 엣지 캐시 60초(같은 날 값이 조금 늦게 바뀌어도 됨). 표본 < 50이면 `{sample}`만 돌려주고 화면은 줄을 숨긴다.
- **개인정보**: 이름·계정 없음. pid = 기기 로컬 무작위 id(이미 `getPid`), IP는 해시만, 응답에 다른 사람의 행을 내보내지 않는다(퍼센트·표본 수만). 보관 30일 뒤 삭제(크론 없으면 제출 때 `DELETE … WHERE day < 오늘-30` 한 줄).
- **위조 방어(단계)**: ① 지금 수준 — lh·범위·시간당 40회 제한(spill_seen과 같은 IP 레이트리밋), pid당 1행. 퍼센트는 순위표가 아니라 '나만 보는 한 줄'이라 위조 이득이 작다. ② 필요해지면 — Spill은 CPU 160×240 결정적 시뮬이라 리플레이(`play/replay.ts` 형식)를 같이 받아 Worker에서 재시뮬해 moves·ticks를 서버가 직접 계산(CPU 시간 측정 후 결정, 레벨당 수십 ms 예상 — 실측 필요).
- **클라이언트 연결**: DailySpill.onCleared에서 공식 기록일 때만 제출 → 응답(또는 standing GET)을 `DailyClear.standing`으로. 결과 화면은 이미 그 값을 받는다(코드 변경 = DailySpill 몇 줄 + api.ts 함수 1개).
- **프리뷰**: #76(오너 11-20)으로 프리뷰 Worker는 같은 D1을 읽기만 하고 /api/* 쓰기는 403 — 새 제출 라우트도 그 규칙 아래에 두면 프리뷰 제출이 prod 집계에 섞이지 않는다. 남은 오너 결정은 집계를 만들지(우선순위)뿐.
