# 스펙: 레벨 갤러리 v1 (큰 기능 후보 1)

## 목표와 사용자 가치
방문자가 직접 Spill 레벨을 만들어 공개하고, 남의 레벨을 플레이·투표한다. 팀이 하루 1레벨로 쌓는 속도의 한계를 넘고(사용자 생성 콘텐츠), 만든 레벨 링크를 공유하는 재방문 동기가 생긴다. 결정 근거: DECISIONS 11-10(에디터 공개 → 솔버 검증 통과분만 발행).

## 완료 조건
- `/spill/editor`가 공개되고, 발행 전 솔버(현 `spill:verify`와 같은 코어)가 "클리어 가능 + 방치 시 미클리어"를 확인한다.
- 통과한 레벨만 D1에 저장되고 `/play/community/<id>`에서 플레이된다. 목록 `/play/community`(최신·인기).
- 댓글 없음(CLAUDE.md). 투표는 레벨당 IP 1회(기존 갤러리 방식 재사용).
- 광고는 목록·플레이 화면에 넣지 않는다(verify-ads 허용 목록 유지).

## 측정 지표 (같은 PR에 계측)
`level_publish`, `community_play`, `community_clear`, `community_vote` AE 이벤트(ref = 레벨 id가 아니라 'list'/'play' 같은 고정 값 — 카디널리티 보호).

## 하지 않을 것
계정·프로필, 댓글, 순위표, 격자 크기 변경, 공유 URL 형식 변경, 시뮬 품질 작업.

## 단계
1. D1 스키마 + 발행 API(검증 서버측 재실행) 2. 에디터 공개 + 발행 UI 3. 목록·플레이·투표 4. 계측·검증 스크립트(`verify-community.py`).
리스크: 서버측 솔버 CPU 시간(Worker 한도). 한도를 넘으면 클라이언트 검증 결과 + 서버 재생 검증(기록된 수순 1개 재생)으로 줄인다.
