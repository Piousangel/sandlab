# Sandlab Spill: 퍼즐 모드 최종 설계안 (리드 디자이너 / PO, 비평 반영본)

입력 자료는 다음과 같습니다.
- 초안
- 플레이어/재미 비평과 실현성 비평
- 핸드오프
- 사용자 폰 스크린샷
- 레포 확인 결과
  - `materials.ts`: 재료 ID가 PRESETS 순서에 묶여 있습니다. 불 수명 45틱, 증기 160틱, 연기 120틱입니다.
  - `wrangler.jsonc`: assets가 먼저 응답하고, 워커는 `/api/*`와 `/s/*`만 처리합니다.
  - `src/lib/challenge/*`: 현행 모듈입니다.

모바일 UX, 경쟁·리텐션, 엔진 영역은 리드가 직접 채웠습니다. 해당 부분은 **[리드 판단]**으로 표시했습니다.

## 0. 한 페이지 요약

**이름은 Sandlab Spill이고, 데일리는 "Spill #N"입니다.** Spill #1은 Spill 데일리를 출시하는 날 새로 시작합니다.

**확정 결정 9개**
1. **퍼즐 전용 세로 격자는 160×240셀입니다.** 배치는 4×4셀 타일(40×60) 단위로 스냅합니다. 샌드박스 1200×600은 바이트 하나도 건드리지 않습니다.
2. **퍼즐 시뮬은 퍼즐 전용 물리를 쓰는 CPU 결정적 TS 엔진입니다.** 렌더는 Canvas2D이고, 재료 테이블과 ID 공간도 따로 둡니다. 샌드박스 커널을 포팅하거나 GPU와 맞추는 것이 목표가 아닙니다. 목표는 **게임에 맞게 튜닝하고 스스로 일관된 물리**입니다. 대표 예가 액체 수평 확산 패스로, 1초에 40셀 이상을 목표로 합니다.
3. **점수는 수(moves)와 시간(틱)으로 매깁니다.** 타일 스냅 덕분에 시간 차이는 손재주가 아니라 경로를 고른 결과가 됩니다. 수는 Run을 누르는 순간 확정된 액션만 셉니다. Setup 단계에서 Undo는 무제한입니다.
4. **레벨이 재료를 주고, 플레이어는 길을 냅니다.** 흐름은 Setup → Run → 즉시 Retry(배치 유지)입니다. 실패는 1.5초 안에 판정합니다.
5. **목표는 래치 타깃입니다.** 마지막 타깃이 래치되는 그 틱에 CLEAR입니다.
6. **별은 ★Clear, ★Gems, ★Par입니다.** Par = 수 ≤ parMoves **그리고** 시간 ≤ parSecs입니다. 이렇게 하면 1수 레벨에서도 변별력이 생깁니다. Crown은 출시 후로 미룹니다.
7. **데일리는 Run 5회 제한(Wordle식)입니다.** 런별 공유 그리드를 쓰고, 전역 순위표는 두지 않습니다. 비교 축은 친구 도전장과 런 수 분포입니다. **서버 재시뮬과 Workers Paid가 필요 없습니다.**
8. **데일리 공급은 템플릿 × 변형자를 생성기와 솔버 검증으로 반자동화합니다.** 출시 버퍼는 14개이고, 바닥나면 재방송합니다. 내부 에디터는 S2로 앞당깁니다.
9. **OG 개인화 문구는 D1에 저장된 레코드(`r=runId`)에서만 가져옵니다.** URL 쿼리는 무시합니다.

**출시 순서**
- S0 엔진 스파이크와 S1 샌드박스 레이아웃/OG 핫픽스는 병렬로 진행합니다. S1은 오늘 바로 배포할 수 있습니다.
- S2: 코어 + W1 + 에디터/검증 (첫 공개 슬라이스)
- S3: 데일리 v2 + 공유 + 도전장
- S4: W2·W3 + 월드 지도 + 클립
- S5: W4 + 포털, 순위표 재검토

## 1. 비전과 플레이어 판타지

**판타지:** "쏟아지는 재료를 내가 단 몇 수로 길들인다." 둑 한 줄을 파면 물이 수로를 타고 달려 냄비에 '딩' 하고 찹니다. 그리고 친구에게 "나 2번 만에 깸"이라고 던집니다.

**경험 원칙**
- **시뮬이 볼거리를 맡고, 플레이어는 생각을 맡습니다.** 손재주는 점수에 영향이 없습니다. 타일 스냅과 일시정지 중 Trigger 허용이 그 장치입니다.
- **실패에서 다음 시도까지 마찰은 0입니다.** 1.5초 안에 실패를 판정하고, ↺ 한 번이면 300ms 안에 Setup으로 돌아갑니다. Undo도 무제한입니다. 깨는 맛의 절반은 여기서 나옵니다.
- **원인과 반응은 같은 틱에 맞춥니다.** 래치되는 틱에 소리, 플래시, 흔들림, 파티클이 함께 나갑니다. iOS와 음소거 환경에서도 시각 효과만으로 충분히 느껴져야 합니다.
- **세로 폰이 1급 시민입니다.** 데스크톱은 같은 캔버스에 사이드 패널을 붙입니다.
- **하루 3분.** 데일리는 최대 5런이고 2~5분 안에 공유까지 끝납니다.

## 2. 코어 루프와 메타 루프

**코어 루프 (레벨 1판, 30초~3분)**
```
진입 → Setup(정지): 타일 스냅 배치, Undo 무제한, "0 moves · par 2 / 6.0s"
  → ▶ Run (1x/2x/4x; 상한은 기기 실측으로 자동 결정)
     Run 중: ⏸ 가능, 정지 상태에서도 Trigger 허용 (반응속도 무관)
  → 타깃 래치마다 즉시 반응 → 마지막 래치 = CLEAR (같은 틱)
  → 실패 판정(§4.2, 1.5초 이내) → "1 target left" → ↺ (배치 유지, 300ms)
  → 결과 카드: ★Clear ★Gems ★Par · 분포 내 위치(표본이 50 이상일 때만) · Next / Share
```

**메타 루프**
- **캠페인:** 레벨 목록(S2) → 월드 지도(S4). 다음 월드는 별 16/24(8레벨 기준)에서 열립니다.
- **일일:** Spill #N → 5런 안에 클리어 → 런별 그리드 공유 → 친구 도전장 → 내일 다시 와서 연속 기록.
- **설욕:** 도전장 링크 → 상대 기록 배너 → 클리어 → "You beat 민수: 2 runs vs 3" → 되갚기 공유.

## 3. 화면 (세로 우선) [리드 판단]

### 공통 레이아웃 규칙
- **높이 배분**
  - 높이는 `100dvh` 기준입니다. 헤더 44px, 캔버스, 트레이 1행 64px, `env(safe-area-inset-bottom)` 순으로 쌓습니다.
  - 남는 세로 공간은 0입니다. 캔버스 아래가 남으면 캔버스를 키우고, 폭에 막혀 더 못 키우면 그 공간을 트레이 높이로 흡수합니다.
- **캔버스 배율**
  - CSS 배율은 `s = floor(min(availW, availH*2/3) * dpr / 160) / dpr`로 정하고, `image-rendering: pixelated`를 씁니다.
  - 기기 픽셀 기준으로 정수 배율이 되게 하는 것이 목적입니다. 사용자 폰 DPR 2.8125 기준으로 셀은 약 1.8~2.1 CSS px입니다.
- **트레이와 보조 버튼**
  - 트레이 1행에는 동사 버튼들과 ▶ Run만 둡니다.
  - ↺, Undo, ⏩는 **캔버스 우하단 플로팅 버튼**입니다. 크기 44px, 반투명입니다.
- **메시지 슬롯**
  - 메시지 슬롯은 하나뿐이며 캔버스 안 상단 중앙에 둡니다. 토스트, 힌트, 실패 문구가 모두 여기에 뜹니다. 헤더에는 텍스트 알림이 나오지 않습니다.
- **헤더**
  - 폭이 400px 미만이면 내비게이션을 ☰로 접습니다.
  - 헤더에는 뒤로가기, 레벨명, 수/Par, 사운드 토글, ⏸만 둡니다.
- **조작과 데스크톱**
  - 탭 타깃은 최소 44px입니다.
  - 데스크톱(900px 이상)은 캔버스를 가운데 두고, 오른쪽 패널에 목표, 별, 분포, 레벨 설명 SEO 텍스트를 넣습니다.
- **완료 기준 스냅샷:** 360×640, 390×844, 카톡 인앱 바를 반영한 360×540, 1440×900.

### 3.3 플레이 HUD
```
┌──────────────────────────┐
│ ← 2-3 Fuse  1 move · par 2 / 6.0s  🔊 ⏸│
├──────────────────────────┤
│  · Light it from below   │ ← 메시지 슬롯
│   [캔버스 160×240]        │   Setup: 합법 타일 옅은 하이라이트
│   (횃불) (젬 24px+)       │   타깃: 래치 전 펄스
│                 (⟲)(↺)(⏩)│ ← 플로팅 Undo/Retry/FF
├──────────────────────────┤
│ [⛏Dig][✦Spark 1][━Fuse 1]  [▶ RUN] │
└──────────────────────────┘
```
- **수 표기:** "N move(s) · par P / T.Ts"로 씁니다. 초과한 항목만 빨간색으로 바꿉니다.
- **Dig / Line:** 드래그하면 시작 타일에서 끝 타일까지 **8방향 직선**으로 스냅합니다. 길이는 레벨의 `maxLen` 타일 이하입니다. 프리뷰는 고스트로 보여 주고, 손을 떼면 확정합니다. 꺾임과 자유곡선은 없습니다. 지그재그로 1수 안에 여러 구간을 파는 것을 막기 위해서입니다.
- **Drop:** 손가락보다 24px 위에 고스트 스탬프를 띄우고, 손을 떼면 놓입니다. 불법 타일이면 빨간 고스트로 표시하고 0수 처리합니다.
- **Trigger:** 게이트 아이콘(44px 히트박스)을 탭합니다. 탭하면 FF가 자동으로 1x로 떨어집니다. 타이밍 창이 열리면 게이트가 깜빡입니다. ⏸ 상태에서도 탭할 수 있습니다.
- **Undo와 Retry:** ⟲ Undo는 Setup에서 마지막 액션을 지우며 무제한입니다. ↺는 Run 중이든 실패 후든 1탭으로 Setup에 돌아가고 배치는 유지합니다. ↺를 길게 누르면 전부 지웁니다.
- 이전 시도의 Run 중 액션은 반투명 유령으로 표시합니다.

### 3.4 클리어 연출
**풀 버전 (첫 클리어와 기록 갱신 때만, 약 2.2초, 탭하면 스킵)**
```
t=0    마지막 래치: 렌더 전용 0.25x 슬로모 0.6s + 타깃 쪽 6% 줌 + 화면 플래시 120ms
       + 캔버스 흔들림 3px + 피치 사다리 최고음 + vibrate(30)
t=0.6  반투명 카드 슬라이드 업 (캔버스는 계속 보임)
       CLEARED!   ★Clear ★Gems ☆Par   (250ms 간격, 각자 소리)
       1 move · 7.2s   (par 6.0s — "0.6s faster than par? Try another path")
       [분포 막대 + ▲you]  ← 표본이 50 이상일 때만
       [↺ Retry] [Share] [Next ▶]
```
- **축약판 (재클리어, 0.6초):** 플래시, 소리, 카드가 나오고 Next에 포커스를 줍니다.
- **신기록 도장:** "NEW BEST".
- **타깃 래치마다:** 피치 사다리 소리, 플래시 60ms, 흔들림 2px, 타깃 위 파티클이 나갑니다. 파티클은 오버레이에만 그리고 시뮬에는 영향이 없습니다.
- **음소거 감지 시:** AudioContext가 `suspended`이거나 사운드 토글이 꺼져 있으면 플래시와 파티클을 1.5배로 강화합니다.
- **`prefers-reduced-motion`:** 줌, 슬로모, 흔들림을 끄고 플래시는 약하게, 카드는 남깁니다. 슬로모는 처음부터 렌더 전용이라 틱 결과와 무관합니다.

## 4. 게임 시스템

### 4.1 동사 (레벨마다 1~3개 허용, 모든 동사 = 1수)

| 동사 | 입력 | 효과 | 제약 |
|---|---|---|---|
| Dig | 8방향 직선 드래그 | 경로 위 타일 안의 `dirt` 셀만 제거합니다. 경로 폭은 1타일(4셀)입니다. | `maxLen` 타일 |
| Drop | 탭 | 스탬프를 놓습니다: 얼음 2×2타일, 스파크 1×1, 산 1×1(액체 16셀). **빈 셀에만** 놓입니다. | 레벨별 충전 수 |
| Line | 8방향 직선 드래그 | `fuse`(정적, 불이 빠르게 전파) 또는 `plank`(정적 나무)를 놓습니다. 폭은 1타일입니다. | `maxLen`, 빈 셀만 |
| Trigger | 게이트 탭 | 해당 `gate` 셀들을 `empty`로 바꿉니다. 1회용입니다. | Run 중 또는 ⏸ 중에만 |

- **수 계산:** Run을 누르는 순간 Setup 리스트에 있는 액션 수와 Run 중에 쓴 액션 수를 더합니다. 시도(런)가 바뀌면 0부터 다시 셉니다.
- **동점 처리:** 같은 수면 틱이 작은 쪽이 앞섭니다. 그다음 동점은 파낸 타일 수가 적은 쪽입니다.

### 4.2 목표 = 래치 타깃

| 타깃 | 센서 | 래치 |
|---|---|---|
| 냄비 (fill) | rect 안에 지정 재료 ≥ need셀 | 도달 순간 영구. 게이지 링 표시 |
| 횃불 (ignite) | rect 이웃에 fire | 즉시 |
| 종 (reach) | rect 안에 steam이나 지정 재료 | 즉시 |
| 상자 (protect) | rect 안의 셀이 `crate` 재료로 유지되는 상태로 holdTicks | 유일한 지속형. 카운트다운 링 |
| 해골 냄비 (bad) | 금지 재료 ≥ need | 즉시 실패 |

- 센서 rect 최소 크기는 2×2타일(8×8셀)입니다. 젬도 같은 규칙을 따릅니다.
- **CLEAR:** 모든 타깃(bad 제외)이 래치되는 틱입니다.
- **실패 판정은 다음 중 하나가 1.5초(90틱) 연속 성립할 때입니다.**
  - (a) 래치나 센서 진척(아무 fill 카운트의 증가)이 없고 이동한 셀 수가 64 미만
  - (b) 모든 source(spout 잔량 + 원래 레벨의 유체)가 정지했고 미래치 타깃이 남음
  - 이 외에 bad 래치, crate 파손이 있으면 즉시 실패이고, 하드캡은 2700틱(45초)입니다.
  - 기체 수명 감소는 "이동"으로 치지 않습니다.
- 센서는 CPU 그리드를 매 틱 읽습니다. 센서 영역 카운트는 증분으로 갱신합니다.

### 4.3 별과 점수
- ★1 **Clear**
- ★2 **Gems:** 1~3개를 모두 획득해야 합니다. 젬 rect 안에 지정 재료가 닿으면 얻습니다. 획득하면 HUD 카운터로 날아가는 애니가 나옵니다.
- ★3 **Par:** 수 ≤ `par.moves` **그리고** 시간 ≤ `par.secs`입니다.
  - `par.secs` = 개발자 최선 틱 × 1.15 (0.1초 단위 올림).
  - 1수 레벨에서도 "더 좋은 경로"가 별을 가릅니다.
- **레벨 작성 규칙:** Par 1 레벨은 클리어하는 1수 해 가운데 `par.secs`를 넘는 해가 반드시 있어야 합니다. 솔버로 확인합니다. 클리어하면 별 3이 자동으로 붙는 레벨은 금지입니다.
- **분포:** 레벨 분포는 (moves, 0.5초 틱 버킷) 2차원으로 저장하고, 표시는 시간 막대로 합니다. 표본이 50 미만이면 숨깁니다.
- **폐기:** 잉크, 잉크 밴드, `inkCap`.
- **Crown(개발자 기록 미만):** S4 이후 지표를 보고 결정합니다.

### 4.4 진행과 저장
- 다음 월드는 별 2×레벨 수에서 열립니다.
- 진행 저장은 localStorage `spill.v1`이고 레벨마다 독립 키입니다(`spill.v1.lvl.<id>`). 한 레벨 데이터가 손상돼도 다른 기록은 살아남습니다.
- 모든 접근은 try/catch로 감쌉니다.
- `pid`는 128bit 랜덤입니다. **6자 복구 코드**는 pid를 짧게 줄인 코드이며, 서버에 `pid ↔ code`를 저장합니다.
  - 서버에는 pid별 데일리 행이 있으므로 연속 기록과 데일리 이력은 서버에서 다시 계산해 복원할 수 있습니다.
  - 캠페인 별은 localStorage에만 두고, 코드 가져오기는 데일리와 연속 기록만 복원합니다.
- 카톡 인앱 UA에서 처음 클리어하면 "Open in Chrome/Safari to keep your streak"와 복구 코드를 **1회만** 보여 줍니다.
- 기존 /play 별 기록은 이관하지 않습니다(사용자 결정 #3).

### 6.1 데일리 Spill [비평 반영: 전면 변경]

### 6.2 순위표: 출시하지 않음 [비평 반영]
- pid는 시크릿 창으로 쉽게 새로 만들 수 있고, 시뮬 코드가 클라이언트에 있습니다. 서버 재시뮬은 합법성만 증명하고 첫 시도였는지는 증명하지 못합니다. 그래서 "✓ 검증 순위표"는 공정해 보이는 착시를 줍니다.
- 대신 조작해도 얻을 게 없는 지표만 둡니다.
  - "solver #N today"
  - 런 수 분포
  - 친구 도전장
- **S5 재검토 조건:** 데일리 DAU가 500 이상일 것. 재검토할 때는 pid당 최고 기록, Watch 본 pid 제외, 상위 50 진입 시에만 재시뮬(Workers Paid) 방식을 씁니다.
- **해법 공개:** 데일리 해법은 **다음 날** 아카이브에서만 공개합니다. 캠페인은 Hint 문구를 먼저 보여 주고, 3회 실패한 뒤에 개발자 해법 리플레이 버튼을 줍니다.

## 7. 기술 아키텍처 [리드 판단, 실현성 비평 대부분 수용]

### 7.1 결정
- 퍼즐 시뮬은 `src/lib/spill/sim/`에 있는 순수 TS 엔진입니다.
- **퍼즐 전용 재료 테이블과 ID 공간을 씁니다.** 색과 발광값은 샌드박스에서 복사해 브랜드 일관성을 지키되, `materials.ts`를 import하지 않습니다.
- 샌드박스 쪽 `materials.ts`, `shader.ts`, `engine.ts`, Params는 **0바이트 변경**입니다. inkCap 관련 죽은 코드는 그대로 둡니다.
- 근거는 네 가지입니다.
  - 기기 간 비트 단위로 같은 결정성이 나옵니다. 리플레이, 도전장, 헤드리스 검증이 이것에 의존합니다.
  - 센서를 매 틱 직접 읽을 수 있습니다.
  - Node 솔버를 돌릴 수 있습니다.
  - WebGPU가 없는 환경(카톡 인앱일 가능성)에서도 돌아갑니다. 다만 사용자 스크린샷은 Android Chrome이었으므로, 카톡에서 실제로 WebGPU가 되는지는 S1 계측으로 확인합니다.

### 7.2 시뮬 명세
- **그리드 저장**
  - `W=160, H=240`.
  - `mat: Uint8Array(38400)`, `life: Uint8Array(38400)`, `moved: Uint8Array(38400)`(틱 내 중복 이동 방지).
- **틱 순서** (60틱/s)
  1. 적용할 액션
  2. Margolus 2×2 패스. 오프셋은 `tick&1`로 (0,0)과 (1,1)을 번갈아 씁니다. 밀도와 movement 규칙은 샌드박스 의미론을 따릅니다.
  3. **수평 확산 패스.** 아래로 못 떨어지는 액체 셀은 방향 `d = ((y + tick) & 1) ? +1 : -1`로 행을 스캔하면서, 같은 밀도 이하의 빈칸으로 최대 `spread[mat]`셀 이동합니다(water 1, oil 1, acid 1, lava는 짝수 틱에만 1). 목표치는 평평한 바닥에서 1초에 40셀 이상입니다.
  4. 반응 패스(이웃 4방향)
  5. 수명 감소
  6. spout 방출과 vent 소거
  7. 센서 갱신
- **결정성 규칙**
  - RNG는 `h = hash32(x>>1, y>>1, tick, levelSalt)`로 만들고, 내부 연산은 `Math.imul`과 `>>>0`만 씁니다.
  - 확률 비교는 `(h & 0xffff) < chanceQ16`입니다.
  - 부동소수점과 `Math.random`은 쓰지 않습니다. 린트 규칙으로 sim 디렉터리에서 금지합니다.
- **퍼즐 재료 (ID 고정, 추가는 끝에만)**
  `0 empty, 1 wall, 2 dirt, 3 stone, 4 wood, 5 plank, 6 metal, 7 ice, 8 sand, 9 water, 10 oil, 11 acid, 12 lava, 13 fire, 14 steam, 15 smoke, 16 fuse, 17 gate, 18 spout, 19 vent, 20 crate`
  - `spout`는 정적 셀입니다. 레벨 데이터의 `{mat, rate/틱, total}`에 따라 바로 아래 빈칸에 재료를 방출하고, 잔량은 센서 판정에 씁니다.
  - `vent`는 닿은 기체를 지웁니다.
  - `gate`는 wall과 같지만 Trigger로 지울 수 있습니다.
- **반응표 (Q16 확률/틱, 쌍마다 최대 4개)**
  - water + lava → stone + steam (1.0)
  - water + fire → steam + empty (0.5)
  - fire + wood → fire (0.08). wood는 life 기반으로 약 2초 버팁니다.
  - fire + plank → fire (0.15)
  - fire + fuse → fire (0.9). 전파 속도 약 50셀/s입니다.
  - fire + oil → fire (0.5)
  - lava + wood/plank → fire (0.3)
  - ice + fire/lava → water (0.1). **ice + water 동결은 없습니다.**
  - acid + metal/stone/wood/plank → smoke + 확률적 acid 소모 (0.05)
  - acid + water → steam (0.2)
  - dirt와 wall은 모든 반응에서 불활성입니다.
- **수명 (격자 축소에 맞게 재설정):** fire 24, steam 90, smoke 60.
- **물리 목표치 (S0에서 벤치 레벨로 측정해 확정, 미달이면 규칙 상수를 조정)**
  1. 물 수평 이동이 1초에 40셀 이상
  2. 냄비 400셀이 정상 유량에서 3초 이하로 참
  3. plank 1타일이 1.5~3초에 관통됨
  4. 1타일 용암 시트 위로 물을 보내면 stone 크러스트가 생기고 증기가 오름
  5. 아래에서 점화하면 wood가 탐
  6. fuse 40셀 전파가 1초 이하
  7. 하드캡 동안 증기가 천장 vent에 쌓이지 않음

### 7.3 실행 루프와 성능
- **실행 위치:** 시뮬과 컨트롤러는 React state 밖의 클래스입니다(`SpillController`). React는 HUD만 구독합니다.
- **틱과 FF**
  - 누산기 고정 틱입니다. FF는 프레임당 틱 수(1/2/4)를 늘립니다.
  - 프레임 예산(12ms)을 넘으면 틱을 버리지 않고 시뮬을 느리게 돌립니다.
  - FF 상한은 처음 2초 동안 잰 평균 틱 ms로 자동 결정합니다: 2ms 이하면 4x, 4ms 이하면 2x, 그 외에는 1x.
- **스킵 최적화:** dirty-chunk 스킵은 **처음엔 쓰지 않습니다.** 측정에서 1x가 3ms를 넘을 때만 도입하고, 완전히 빈 청크와 불활성 정적 청크만 건너뜁니다. 건너뛸 때와 안 건너뛸 때 결과가 같은지를 vitest로 강제합니다.
- **Web Worker:** S0 벤치에서 사용자 폰의 1x 틱이 4ms를 넘으면 시뮬을 Worker로 옮깁니다. 그리드를 transfer하고 메인에서는 렌더만 합니다.
- **S0 게이트:** 사용자 폰(Chrome, 그리고 카톡 인앱 1회)에서 `/spill/bench`가 2x 이상을 유지해야 합니다. 실패하면 격자를 128×192로 줄입니다.

### 7.4 렌더
- **본 레이어:** `ImageData(160×240)`를 `putImageData`로 그리고, CSS로 확대하며 pixelated로 처리합니다. 색 노이즈는 셀 좌표 해시로 고정합니다. 액체 윗면 1셀은 하이라이트로 그립니다.
- **발광 레이어:** 40×60 저해상 캔버스에 발광 재료 합계를 쓰고, `imageSmoothingEnabled=true`로 확대한 뒤 `globalCompositeOperation='lighter'`로 합성합니다. `ctx.filter`는 쓰지 않습니다.
- **오버레이 캔버스:** 타깃·젬 스프라이트(최소 24 CSS px), 고스트, 래치 FX, 흔들림, 플래시를 그립니다.
- **소리와 진동:** WebAudio 합성 사운드로 에셋은 없습니다. `navigator.vibrate`는 있으면 씁니다.
- **S0 완료 기준:** OG 1장 시안을 사용자가 승인해야 합니다. "싸구려 데모처럼 보이는지" 확인하는 단계입니다.

### 7.5 데이터 포맷
**레벨 (TS, 맵 축척 1/2: 문자 1개 = 2×2셀, 80×120자)**
```ts
export default defineLevel({
  id: '1-3', v: 1, world: 1, name: 'Two Pots', salt: 0x3a1f,
  legend: { '#':'wall', '.':'empty', 'd':'dirt', 'w':'water', 's':'sand', 'G':'gate:g1', 'S':'spout:s1' },
  map: `...80 cols x 120 rows...`,
  spouts: { s1: { mat:'water', rate:2, total:1200 } },
  targets: [{ id:'a', kind:'fill', rect:[tx,ty,tw,th], mat:'water', need:400 }],
  gems: [{ rect:[tx,ty,2,2], mat:'water' }],
  verbs: { dig:{ maxLen:20 }, drop:null, line:null, trigger:['g1'] },
  legalTiles: 'auto',           // dig: dirt 포함 타일, drop/line: empty 타일
  par: { moves:2, secs:6.0 },
  dev: [[0,'dig',12,30,12,44], [0,'dig',20,30,26,44]],
  hint: 'Split the stream.',
})
```
- rect와 좌표는 **타일 단위**(40×60)입니다. 렌더와 센서용 셀 좌표는 ×4로 계산합니다.
- 레벨 해시 `lh` = FNV-1a32(정규화된 JSON).

**리플레이 (JSON, deflate 없음)**
`{ v:1, id:'1-3', lh:'9f2c11ab', a:[[tick, verbCode, tx, ty, tx2, ty2]] }`
- 액션은 최대 32개이고 크기는 보통 150B 미만입니다.
- Setup 액션의 tick은 0입니다. Run 중 액션은 적용되는 틱 경계 번호를 씁니다.
- 일시정지 중 입력은 다음 틱에 적용합니다.

### 7.8 검증 파이프라인
1. **`pnpm test`:** sim 단위 테스트(결정성 스냅샷, 반응, 확산 목표치), 파서, 리플레이 왕복, 실패 판정.
2. **`pnpm spill:verify`** (Node, worker_threads)
   - 레벨마다 다음을 확인합니다: 개발자 해가 클리어하는지, 12초 이하인지, 수와 시간이 par 이내인지, 아무것도 안 하면 실패하는지, salt 16개에서 클리어하는지, Trigger ±10틱에서 클리어하는지, 1타일 이웃 변형의 60% 이상이 클리어하는지, 타이밍 창이 0.7초 이상인지.
   - **솔버:** 수가 par.moves 미만인 해를 찾습니다.
     - 후보 액션 공간이 5,000 이하면 전수 탐색합니다(1수 레벨의 표준). 그 이상이면 5,000개를 샘플링하고 경고합니다.
     - 실패를 조기 판정하므로 한 번 시뮬하는 비용은 0.2초 이하로 봅니다.
   - Par 1 레벨에서 "par.secs를 넘는 1수 해"가 존재하는지 확인합니다.
   - 젬 우회가 강제되는지 확인합니다.
3. **`/spill/editor`** (dev 전용): 맵 텍스트를 편집하면 실시간으로 미리보기를 보여 주고, 개발자 해를 기록하고, verify 버튼으로 같은 검사를 브라우저에서 돌립니다.
4. **`spill-daily-gen`:** 템플릿 × 변형자에서 후보를 만들고 verify를 통과한 것만 `schedule.json`에 추가합니다. 버퍼 일수를 출력합니다.
5. **E2E:** `/play/<id>?autoplay=1`이 개발자 해를 재생해 클리어 카드가 뜨는지 확인합니다. 레이아웃 스냅샷 4종(§3)을 찍고, `verify-ads`에 `/play/*`, `/d/*`, `/spill/*`를 추가합니다.

## 10. 지표 (AE + D1, `scripts/spill-metrics.mjs`)

1. **착지 → 첫 액션 전환율:** `puzzle_land`(ua 분류별) 대비 `first_move` 비율입니다. 카톡이 50% 미만이면 다른 작업을 멈추고 착지부터 고칩니다.
2. **W1 퍼널:** 레벨별 시작 → 클리어 → 3★ 비율, 레벨당 평균 런 수입니다. 건강한 범위는 2~6이고, 0이면 너무 쉬움, 15 이상이면 막힘으로 봅니다.
3. **실패 → 재시도 지연 중앙값:** 2초 이하가 목표입니다. 이탈하는 지점도 함께 봅니다.
4. **클리어당 공유 수 × 공유당 착지 수:** 실질 K의 대리 지표이고, 주간 추세로 봅니다.
5. **데일리 연속 참여율:** 어제 제출한 pid 중 오늘도 제출한 비율의 7일 이동평균입니다. 런 수 분포도 함께 봅니다. 평균이 1.5 미만이면 너무 쉽고, X 비율이 30%를 넘으면 너무 어렵습니다.
6. **도전장 루프:** `r=` 착지 → 클리어 → 되갚기 공유 비율입니다.
7. **보조 지표:** 재방송 일수, 복구 코드 사용 수, `gpu_unsupported` 비율(카톡).
