## 3. 슬라이스 범위 (stage:slice에서 할 일 — 지금은 계획만)
- 렌더만: `src/lib/spill/render/{canvas,glow,overlay}.ts` 색·명암 규칙, 보드 프레임(CSS), 목표 오브젝트(overlay), 클리어 순간(fx). **시뮬·`sim/materials` 동작·레벨 데이터·URL·격자·레벨 id 무변경**. 재료 표시 색을 바꿀 때 `MATS.color`를 바꾸지 말고 렌더 팔레트에서 덮는다(시뮬·썸네일·공유 이미지 영향 차단 — 썸네일까지 바꿀지는 슬라이스 첫 PR에서 결정).
- 1-1~1-3만 대상이지만 렌더 규칙은 전역이다. `SpillRenderer`를 쓰는 곳: SpillPlayer(/play·/daily), SpillEditor, 홈 오늘 카드(`HomeSections.tsx`), DailyStart, SpillBench. 공유 이미지(`shareImage.ts`)는 보드 캔버스를 복사하므로 같이 바뀐다. 반대로 `/play` 전시실 썸네일(`thumbPixels.ts`)은 빌드 때 `MATS.color`로 따로 구워 **옛 톤으로 남는다** → 썸네일을 맞출지는 **시안 선택 때** 정한다(첫 구현 PR로 미루지 않음). 회귀 캡처 묶음 = 1-x·2-x 각 1장 + /daily + 홈 오늘 카드 + 에디터 + 공유 이미지(일반·데일리 모자이크) + /play 전시실.
- 390 빈 공간(D5): 배율 공식은 그대로, MOVES·PAR 줄을 모든 레벨에서 같은 자리로 통일. 수락 기준: 이동 뒤 1-1·1-2·1-3 보드 폭이 390에서 같다.
- **범위 밖(확산 단계로)**: 1440 오른쪽 문서 패널 개편, 칩·Run 버튼 재디자인(이미 출시된 크롬 유지). 클리어 순간(D7: 차오름 + 테두리 빛 + 기존 효과음 재사용)은 카드 범위라 남긴다.

## 4. 관문 1 — 시안 혹평 채점 (통과 전 코드 금지)
요청: `docs/design/asset-requests/challenge-board-v2.json`(#99 요청을 대체) — 1-3 레이아웃 고정, **보드만** 바꾸는 3방향 pro 3장(헤더·칩·컨트롤은 현 상태 유지, 셀 1개 ≈ 2px라 셀보다 작은 디테일 금지) + 현 화면 혹평 1건(S1~S6과 같은 축 = 기준선). 비용 ≈ ₩194×3 + 혹평 1 ≈ **₩700 이하**(카드 상한 ₩3,000). 시안은 방향 선택용 '목표 화면'이라 GEMINI.md G3대로 pro(초안 flash 규칙의 예외 — 방향 판정이 flash 품질에 끌려가지 않게).
- A 유리 표본 상자(따뜻한 에스프레소 그라데이션 + 사암) · B 종이·석회암 단면(밝은 보드) · C 밤 실험실 램프(청흑 + 슬레이트).

**채점표**(다음 run이 시안 3장 + 현 화면에 매김. 채점자 = 작성 세션과 다른 `reviewer` 서브에이전트 + Gemini 혹평(시안 3장을 함께 보는 critique 1건을 다음 run이 추가, ≈ 소액) — 생성 모델의 자기 채점 편향은 reviewer 점수를 우선해 상쇄, 둘 다 기록)
- **격자 사본 먼저**: 채점 전에 시안의 보드 영역을 160×240으로 줄였다가 nearest-neighbour로 다시 키운 사본을 만들고(`scripts` 없이 Pillow 한 줄), **S2·S4·S6은 그 사본으로만** 매긴다 — 원본의 매끈한 질감에 속는 '그럴듯한 통과'를 막는다.
- 7점 앵커 = '홈 시험관 도크 옆에 놓아도 이질감 없다'. 시안에 글자·숫자가 섞이면 그 시안은 탈락.
| 항목 | 질문 | 통과선 |
|---|---|---|
| S1 톤 통일 | 보드가 크림 페이지·시험관 도크·홈 붓기 캔버스와 같은 앱으로 보이나 | ≥7 |
| S2 재질 | 돌·흙·물·빈 공간이 셀 명암만으로 구분되나(흑백 변환해도) | ≥7 |
| S3 목표 위계 | 처음 보는 사람이 3초 안에 '어디를 무엇으로 채우나'를 아나 | ≥7 |
| S4 구현 가능성 | 160×240 셀 색·그라데이션·윤곽만으로 재현되나(3D·사진 질감 없음), 60fps | ≥7 (미달이면 탈락) |
| S5 대비·접근성 | 재료 대비, 색각 이상 시뮬에서 목표·위험 구분(칩 글자 대비는 구현 PR의 `contrast` 검사로) | ≥7 |
| S6 Sandcastle급 '마감' | 스크린샷 한 장이 Steam 상점 이미지로 쓰여도 어색하지 않나 | ≥7 |
- **통과** = 한 시안이 6항목 모두 통과선 이상 + 평균 ≥7.5. 못 미치면 가장 높은 시안으로 프롬프트를 고쳐 1회 재생성(≤3장), 그래도 미달이면 결정 요청(방향 자체 의심).
- 현 화면(before) 점수는 기준선으로 같이 남긴다(예상 4점대). 구현 후 G4 혹평은 ≥7(카드 목표가 'Sandcastle급'이라 기본 6.5보다 높임).

## 6. 버린 대안 (3)
1. **배경 그림(해변·실험실 일러스트) 깔기** — itch 불평 '사실적 배경 + 추상 퍼즐 요소 충돌', LCP 부담. 셀 명암 규칙이 더 싸고 일관.
2. **WebGL 셰이더(굴절·법선)로 재질** — 새 렌더 경로 위험(WebGPU 없는 폰 8건, 렌더 테스트 재작성). 지금 ImageData 경로에서 명암 규칙으로 충분한지 먼저 본다.
3. **레벨 1-1~1-3만 별도 스킨** — 확산 때 두 벌 유지, 데일리와 톤 갈림. 전역 규칙 + 회귀 캡처로 간다.

## 7. 프리모템 (오너가 10분 플레이 뒤 '아직 대충'이라 한다면)
